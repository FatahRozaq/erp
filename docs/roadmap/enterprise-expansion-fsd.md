# FSD-EXP — Enterprise Expansion final

**Batas produk yang diputuskan untuk roadmap ini:** discrete assembly ringan, POS online dengan payment provider yang diadaptasi, TMS milestone/carrier tanpa optimasi rute atau live telemetry, analytics/forecasting sebagai keputusan bantu, dedicated reporting store, dan opsi service split terukur. Ini mengoperasionalkan [PRD §54](../enterprise-erp-prd.md#54-product-roadmap) tanpa mengklaim MRP penuh, process manufacturing, loyalty, offline cash register, fleet optimization, atau autonomous AI posting. Kebutuhan itu menjadi perubahan scope PRD tersendiri. Owner: Operations/Finance untuk assembly, Commercial/Finance untuk POS, Operations untuk TMS, Platform/Data untuk analytics.

## 1. Discrete assembly

BOM `(entity,finished_sku,version,effective_range)` memuat component SKU/base qty, yield, scrap allowance, UOM conversion snapshot; satu versi PUBLISHED pada tanggal bisnis. Work order `DRAFT→RELEASED→IN_PROGRESS→COMPLETED|CANCELLED|EXCEPTION` memuat target qty, warehouse, BOM snapshot, cost policy, batch/serial requirement. Release memeriksa policy/period, mengunci component availability dan membuat reservation; tidak mengurangi stok. Issue membuat movement `SELLABLE→WIP` per component portion; completion mengonsumsi WIP dan membuat finished goods receipt serta jurnal WIP→inventory dalam owner transaction/Finance posting intent yang terlacak. Partial completion dan scrap menyimpan actual qty/cost, bukan mengubah BOM. Variance `actual−standard/snapshot` masuk account rule terbit; tidak boleh auto-post bila mapping hilang. Dua work order tidak boleh memakai serial/component unit sama. Contoh BOM A membutuhkan 2×B @10 dan 1×C @5; WO 3 A mengissue 6 B+3 C bernilai75, completion 2 A bernilai50 dan WIP sisa25 sebelum scrap/selesai. Closed period dan reversal memakai dokumen baru.

## 2. POS online

Store/register/shift berada dalam satu legal entity dan branch scope. Shift `OPEN→CLOSING→CLOSED`; satu active shift per register, cashier tidak dapat menutup shift sendiri bila policy maker-checker. Checkout memerlukan cart price/tax snapshot, stock reserve/consume ack, payment authorization/capture idempotent, receipt number dari owner, dan Finance posting; state `PENDING_PAYMENT|PENDING_STOCK|COMPLETED|EXCEPTION|VOIDED`. Ketidakpastian provider atau stok tidak menghasilkan receipt COMPLETED; reconciler memeriksa provider status sebelum retry/refund. Uncaptured authorization dapat void; transaksi completed dikoreksi via return/credit memo, bukan delete. Refund menautkan source sale dan payment, qty/value tidak melebihi sisa eligible, approval threshold, provider reference unik. Cash drawer close membandingkan expected vs counted, selisih memerlukan reason/approval dan jurnal baru. Contoh 2 unit @100+PPN efektif11% = 222; provider capture222, stock−2, revenue200, tax22, COGS dari cost snapshot; retry key sama tetap satu sale/capture. Terminal offline tidak menerima sale final pada baseline ini.

## 3. TMS milestone

Transport plan `DRAFT→ASSIGNED→IN_TRANSIT→DELIVERED|EXCEPTION` mengelompokkan delivery shipment GUID yang sudah DISPATCHED, carrier, vehicle/driver reference, route sequence dan ETA. Assign tidak mengubah stok/revenue; WMS delivery tetap sumber truth shipped/POD. Milestone `PICKUP|ARRIVAL|ATTEMPT|DELIVERED|FAILED` append-only dengan occurred/recorded time, source device/provider ID dan evidence hash. Duplicate provider event dedup `(connector,external_id)`, out-of-order disimpan lalu diproyeksikan menurut sequence/source time yang valid. `DELIVERED` TMS bukan POD accepted; Finance invoice tetap bergantung pada WMS POD. Carrier charge memerlukan vendor invoice/PO atau accrual rule Finance, bukan langsung dari status TMS. Missing proof, route mismatch, carrier revoked dan late milestone menjadi exception.

## 4. Reporting store, analytics, forecasting

Dedicated reporting store menerima event/CDC terverifikasi per owner dengan schema version, tenant/entity scope, source watermark dan hash; akses read-only, tidak menulis command atau ledger. Model semantik menetapkan definisi gross/net revenue, COGS, fill rate, DSO, stock turnover, return rate, dan FX view dengan formula version serta rekonsiliasi ke Finance/Operations. Dashboard wajib menampilkan `as_of`, watermark lag, entity/currency dan drill-down ke source berizin; stale data tidak ditampilkan sebagai realtime. Forecast demand memakai dataset lineage, train cutoff, model version, horizon, confidence/quality metrics, drift monitor dan approval sebelum recommendation dipakai; output hanya saran PR/replenishment, tidak otomatis membuat PO atau mengubah price. PII minimization, retention dan tenant isolation berlaku pada dataset serta export. Contoh projection kehilangan 1 event: watermark gap memicu `STALE`/DLQ dan export resmi ditahan sampai replay/reconcile, bukan menebak angka.

## 5. Selective service split

Finance/Accounting atau modul lain hanya dipisah bila volume, ownership, deployment cadence atau failure isolation terbukti memerlukan. Rencana split wajib ADR baru: source-of-truth per tabel, expand/backfill/switch/contract, dual-read comparison, outbox/inbox, pending/exception state, reconciliation zero unexplained delta, rollback ke binary lama selama schema kompatibel, dan cutover checkpoint. Invoice tidak boleh `ISSUED` sebelum journal posted; bila split memutus transaksi lokal, gunakan `POSTING_PENDING/POSTING_EXCEPTION` eksplisit dan Finance close menolak pending. Tidak ada dual writer pada tabel yang sama. Split bukan syarat selesai roadmap bila metrik tidak membenarkannya.

## 6. Kriteria penerimaan final

WO partial/WIP/cost/serial dan variance reconcile; POS provider timeout/retry/stock race tidak double capture/sale; TMS late event tidak mengubah POD/GL; reporting store tenant scope/watermark/replay cocok dengan owner; forecast tidak punya jalur posting; service split jika dilakukan lulus dual-run dan rollback. Detail data, command/API/event, UX, serta vektor uji ada di [paket roadmap](README.md). Business case dan aset vendor nyata disetujui sebelum aktivasi, sedangkan baseline sintetis cukup untuk mulai implementasi bounded scope ini.
