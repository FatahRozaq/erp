# FSD-P2 — Phase 2 Operations

**Scope:** RFQ/vendor comparison/blanket PO (F-13), purchase return dan sales return/memo (F-12), transfer/bin/wave/opname, route/visit, mobile offline (F-11), push notification, expanded reports. **Owner:** Commercial, Operations, Finance, Platform. Baseline satu transaksi per legal entity; intercompany menunggu Phase 3. Semua command memakai permission+scope, idempotency, ETag bila aggregate mutable, audit dan outbox menurut [standar](../engineering/README.md). [Return FSD](../features/returns-fsd.md) dan [SYNC-001](../features/mobile-sync-protocol.md) tetap detail kanonik untuk dua alur tersebut.

## 1. RFQ, quotation, award, dan blanket PO

RFQ dari PR APPROVED menyimpan `pr_revision`, line base qty/UOM, invited vendor account, deadline, evaluation policy version, dan terms. State `DRAFT→OPEN→CLOSED→AWARDED|CANCELLED`; quote vendor `DRAFT→SUBMITTED→REVISED/EXPIRED`. Buyer tidak boleh mengubah bobot evaluasi setelah OPEN; perubahan material membuat RFQ revision baru dan semua bid lama tidak eligible. Quote rahasia per vendor; buyer/approver melihat setelah deadline atau semua vendor submit sesuai policy. Perbandingan menormalkan UOM dan currency dengan snapshot kurs terpercaya pada satu `comparison_at`, menyimpan nilai net, tax, shipping, lead time, quality score, total score, dan perbedaan angka; missing FX/UOM menolak award. Skor weighted deterministic; keputusan dengan skor bukan tertinggi memerlukan reason+approver terpisah. Split award per PR line memiliki `sum(awarded_qty_base)≤approved_pr_qty_base`; transaksi Commercial mengunci counter PR line. PO dibuat melalui command PO normal dengan `award_guid`/quote version permanen. Duplicate award tidak membuat PO ganda.

Blanket contract `DRAFT→APPROVED→ACTIVE→EXHAUSTED|EXPIRED|CANCELLED` menyimpan vendor/entity, currency, effective dates, line cap qty dan gross base, pricing/tax snapshot. `ReleaseBlanketPO` mengunci contract+line, menghitung `available=cap−active_releases−consumed`, membuat release reservation dan PO DRAFT dalam satu transaksi Commercial; dua buyer paralel tidak melampaui cap. Pembatalan PO hanya melepaskan sisa yang belum diterima/invoiced. Contoh cap 100 unit, release 60+40 sah, release 1 berikutnya 422 `CONTRACT_CAP_EXCEEDED`; quote 2 carton pada conversion 12 pcs membandingkan 24 pcs, bukan angka 2.

## 2. Return dan memo dua arah

Sales return memakai [FSD-RET](../features/returns-fsd.md): accepted return sebelum invoice mengurangi eligible invoice; sesudah invoice membuat credit memo dengan snapshot harga/tax/cost asal, GL inverse baru dan referensi faktur pajak asli. Purchase return memakai sumber GRN line dan vendor invoice line: approved qty tidak melebihi `received−previously_returned`, inspect menandai sellable/hold, dispatch ke vendor mengurangi stok dengan movement baru. Sebelum vendor invoice, return mengurangi GRNI eligible; sesudah invoice, Finance membuat supplier debit memo yang menurunkan AP dan tax input menurut rule terbit. Refund/offset pada payment existing tidak mengedit posting lama. Periode CLOSED memakai periode OPEN baru dengan link source dan exception pajak bila dokumen koreksi eksternal belum sah. Memo `DRAFT→APPROVED→ISSUED→SETTLED`; satu source portion+memo action unik. Contoh GRN 10 @100, invoice 10, return 3: debit memo net 300 dan input tax 33 pada fixture PPN efektif 11%; inventory turun menurut cost snapshot tiga unit. Return tanpa source/serial cocok ditolak.

## 3. Transfer, bin, wave, dan stock count

Transfer intra-entity `DRAFT→APPROVED→PICKING→PARTIALLY_SHIPPED→IN_TRANSIT→PARTIALLY_RECEIVED→RECEIVED|CLOSED`; cancel hanya qty belum shipped. Source warehouse dan destination dalam entity yang sama. Ship mengunci balance source, reservation, transfer line; sellable turun dan in-transit naik satu transaksi Operations. Receive mengunci transfer shipment portion, menghasilkan sellable/hold tujuan dan menurunkan in-transit; `received+damaged+discrepancy≤shipped` per portion. Partial receipt tetap open; discrepancy membutuhkan claim, checker, dan adjustment baru, tidak menghapus transit. Cost per unit mengikuti snapshot ship; transfer intra-entity tidak mengakui revenue/COGS. Contoh 10 shipped, 7 received sellable, 2 hold, 1 discrepancy: in-transit tersisa 1 sampai claim diselesaikan, nilai total tetap direkonsiliasi.

Bin aktif per warehouse dengan status/kapasitas/kelas barang dan `(warehouse,code)` unik. Relocation adalah dua movement berpasangan dalam satu transaksi; qty lot/serial, status, dan ownership tidak berubah. Scan salah bin/expired/over-capacity ditolak sebelum movement. Wave `DRAFT→RELEASED→CLOSED` hanya mengelompokkan pick task yang sudah punya reservation; release wave tidak menggandakan allocation atau mengubah stok. Claim task memakai lease berversi. Opname `OPEN→FROZEN→COUNTED→REVIEWED→POSTED`; snapshot watermark dan scope bin/lot; second count untuk selisih di atas threshold; selisih posted lewat adjustment berizin, bukan set balance. Movement selama freeze ditahan atau dipisah dengan watermark/recount policy, tidak diam-diam hilang.

## 4. Route/visit, offline, push, dan report

Route plan berversi mengikat salesman, tanggal entity timezone, customer stops, dan scope; `DRAFT→PUBLISHED→CLOSED`. Visit `PLANNED→CHECKED_IN→CHECKED_OUT|CANCELLED`; check-in/out offline adalah local draft yang dikirim melalui SYNC-001, server memvalidasi assignment, window, device, dan idempotency. GPS opsional dengan consent, akurasi dan waktu; tanpa consent visit tetap sah jika policy membolehkan, GPS tidak dipakai sebagai bukti otorisasi. Target/performance dihitung dari event visit/order authoritative, bukan clock device. Offline order tetap `LOCAL_DRAFT/NEEDS_REVIEW` sampai server menerima; tidak mengurangi stok atau kredit lokal.

Push worker mengirim notification ID minimal (tanpa PII/amount) ke device aktif berizin; klik membuka data lewat API dengan authz ulang. Preference `IN_APP|PUSH|EMAIL` per kategori dan quiet hours, security notification tidak dapat dimatikan bila policy wajib. Dedup `(notification_guid,device_guid,channel)` dan retry/DLQ; token device terenkripsi dan dicabut saat logout/revoke. Expanded report mencakup fill rate, return aging, transfer reconciliation, visit attainment, dan RFQ savings dengan `as_of`, scope, source watermark, formula version, export hash; laporan read-only dan tidak menjadi sumber posting.

## 5. Kriteria penerimaan Phase 2

RFQ award concurrent tidak melebihi PR; contract release concurrent tidak melebihi cap; purchase return dan debit memo tidak mengganda AP/stock/tax; transfer partial dengan discrepancy tetap seimbang; bin relocation tidak mengubah total warehouse; wave tidak mengganda reservation; opname menghormati watermark; offline retry membuat satu order; push scope revoked tidak membuka data; report watermark memperlihatkan lag. Vektor numerik dan failure ada di [QA roadmap](roadmap-test-vectors.md); data, command, API dan UX di [paket roadmap](README.md).
