# CMD-001 — Matriks command lintas MVP

**Status:** baseline perilaku; tiap slice menurunkan field API, DDL dan test sebelum handler. Keputusan angka/akuntansi dari [policy MVP](../decisions/mvp-business-policy.md). Semua command memeriksa actor+permission+tenant/entity/scope+state+policy version, expected aggregate version, idempotency, audit dan outbox dalam transaksi owner. Tabel menyebut efek bisnis akhir; bila melibatkan dua owner, setiap owner commit lokal dan saga menunggu ack, tanpa transaksi SQL lintas owner. Error yang tidak disebut khusus mengikuti [katalog API](../../contracts/openapi/README.md).

| Command / owner | Guard tambahan | Write atomik + event | Hasil/exception |
|---|---|---|---|
| `SubmitSalesOrder` / Sales→Credit | DRAFT, price/tax snapshot, approval threshold; Credit mengunci account dan hitung ulang commitment | Credit commit bucket unik lalu Sales commit nomor+SO revision+audit+`sales.order.submitted.v1`; gagal Sales → kompensasi release | WAITING_APPROVAL setelah kedua ack; credit hold 422 |
| `ApproveSalesOrder` / Policy→Sales | pending step, approver bukan maker, policy version sama | Policy commit decision unik+event; Sales consume dan commit APPROVED_PENDING_RESERVATION | competing approve 409, SoD 403; Sales ack tertunda → pending |
| `ReserveStock` / Inventory | SO approved, per-SKU sellable−reserved cukup; lock balance | reservation unique request, reserved qty, `inventory.stock.reserved.v1` | ALLOCATABLE ack; kurang → BACKORDERED; timeout → pending |
| `CancelSalesOrder` / Sales | qty shipped=0, reason, versi cocok | state CANCELLED, release request idempotent | race reserve/cancel: release eventual; WMS tidak pick sampai ack final |
| `CreatePick/DispatchDelivery` / WMS→Inventory | reservation confirmed, warehouse scope, picked qty≤reserved, FEFO | Inventory commit consume+warehouse→transit movement; WMS ack lalu commit delivery DISPATCHED+`warehouse.delivery.shipped.v1` | tidak ada ship bila credit recheck/period/lot gagal; ack hilang → pending/reconcile |
| `AcceptPOD` / WMS | dispatched qty, proof lengkap, accepted+rejected≤shipped | accepted source portion+cost snapshot, pending Finance, `warehouse.delivery.accepted.v1` | partial tetap terbuka; duplicate proof tidak mengganda |
| `CorrectPOD` / WMS→Finance | checker, proof CLEAN, Finance correction claim HELD sebelum WMS commit; ETag/source revision cocok | correction append-only + signed delta, `warehouse.delivery.pod_corrected.v1`; Finance claim APPLIED saat consumer ack | race invoice issue menang → 422; claim tertunda memblokir invoice, bukan auto-expire |
| `IssueSalesInvoice` / Finance | accepted portion, dispatch posting ada, tax rule aktif, period open | invoice ISSUED+AR/revenue/tax+COGS/in-transit journal satu commit, event | pending/retry bila dependency; source portion unik |
| `PostCustomerPayment` / Finance | bank evidence, allocated≤open AR, currency/FX valid, period open | payment, allocation, AR/bank journal, `finance.payment.posted.v1` | unmatched ke suspense, bukan auto-lunas |
| `ReversePayment` / Finance→Credit | posted original, checker, evidence, period pembalik OPEN; customer receipt memerlukan Credit reversal hold ACTIVE sebelum Finance commit | reversal doc + inverse journal + reopened allocations, `finance.payment.reversed.v1`; Credit release hold setelah bucket applied | original tetap immutable; duplicate reversal 409; hold tak auto-release saat event tertunda |
| `ApprovePurchaseOrder` / Purchase | G-06 threshold+SoD, vendor aktif | PO approved snapshot, `purchase.order.approved.v1` | event mengaktifkan receipt limit Operations |
| `AmendPurchaseOrder` / Purchase→Operations | revision baru, qty baru≥received, checker dan limit lama dilepas/diubah dengan ack | revision snapshot, approval ulang; setelah approve event PO revision baru | old revision/duplicate event tidak menaikkan receipt limit dua kali |
| `PostGoodsReceipt` / Operations | approved receipt limit, qty remaining, warehouse/entity, period | receipt limit+movement+balance+cost pool, GRN posted, `warehouse.goods_receipt.posted.v1` | dua GRN paralel terserialisasi |
| `PostVendorInvoice` / Finance | exact three-way match G-07; input tax evidence | AP/input tax/GRNI journal+invoice sekali | exception tidak menghasilkan AP/jurnal |
| `CloseFiscalPeriod` / Finance | signed status cut-off dari tiap owner: pending relevan=0, posting intent mismatch=0, journal balanced, reconciliation stock/AR/AP=0 | Finance commit period CLOSED, audit, `accounting.period.closed.v1` | 422 `PERIOD_CLOSE_RECONCILIATION_PENDING`; tidak query DB owner lain |

**Race dan recovery:** stok/credit/limit receipt dikunci lalu invariant dicek ulang pada primary DB. Cancel yang menang sebelum reserve menyebabkan reserve ditolak atau hasil reserve segera dilepas; dispatch memerlukan ack final, sehingga tidak bisa memakai state sementara. Event duplicate diproses sekali melalui inbox; gap aggregate_version diparkir dan owner snapshot diambil; retry 40P01/40001 mengulang seluruh transaksi dengan key sama. Finance failure setelah POD meninggalkan state `POD_ACCEPTED_PENDING_FINANCE`; close period menolak sampai resolusi. Perubahan material pada SO/PO menginvalidasi approval dan membuat revision baru; posted journal/stock dikoreksi record baru, bukan edit.

**Verifikasi minimum tiap command:** happy path, invalid state, wrong entity/scope, maker-checker, stale version, duplicate key/body mismatch, dua writer simultan, crash sebelum/ sesudah commit, event duplicate/out-of-order, audit/outbox failure, dan rekonsiliasi. Contoh data angka wajib dari FSD slice terkait.
