# IMP-001 — CSV template dan hasil row MVP

**Status:** kontrak import v1 sebelum parser/worker dibuat. `template_type` pada API adalah `SKU|CUSTOMER|VENDOR|OPENING_STOCK|OPENING_AR|OPENING_AP|COA`; `template_version=1`. Kode pada katalog UI adalah gabungan, misalnya `SKU_V1`. Semua CSV UTF-8 tanpa BOM, comma delimiter, double-quote escaping/multiline sesuai RFC 4180, header exact dan case sensitive, tanggal `YYYY-MM-DD`, angka decimal string dengan titik tanpa pemisah ribuan, boolean `true|false`. Maksimum 10.000 data row, 10.000.000 byte dan 255 karakter per field teks, kecuali batas kolom lebih kecil. Row lebih panjang, kolom tak dikenal, duplicate header, control character, atau encoding rusak ditolak sebelum preview. Formula prefix diekspor dengan apostrof aman dan input tidak dieksekusi. File asli berada di quarantine private; hanya hash/status/row result aman yang masuk database.

`external_id` wajib unik per `(tenant, legal_entity, source_system, template_type)` setelah commit; preview menandai duplicate dalam file atau registry. `legal_entity_code` wajib untuk template entity scoped dan harus sama dengan context `X-Legal-Entity-Guid`, bukan memilih entity lain. `source_system` diberikan pada job create dan disimpan di mapping. Reference `*_code` diselesaikan ke GUID active pada snapshot/watermark preview; commit menolak perubahan snapshot. Kolom kosong hanya boleh untuk field bertanda `?`, tidak menyamakan string kosong dengan nol. `status`, ID internal, actor, version, posting number, dan journal GUID tidak diterima dari CSV.

Kolom `credit_limit_base?`, `lot_no?`, `serial_no?`, `parent_code?`, `currency?` adalah header tetap yang selnya boleh kosong; tanda `?` bukan bagian nama header aktual. Header aktual menghapus `?`. Template stock serial wajib qty tepat 1 per serial. Opening tax status hanya `NOT_APPLICABLE|DOCUMENTED|PENDING_REVIEW`; tidak mengklaim faktur pajak resmi baru. Semua opening balance memakai akun pembukaan yang diaktifkan dan watermark per owner; debit=kredit dan subledger=GL control harus nol delta sebelum gate data cutover.

## Outcome per row dan commit

Row result mempunyai `row_no` 1-based data row, `external_id`, `status=VALID|INVALID|DUPLICATE|COMMITTED|FAILED`, `error_code`, `field`, `safe_message`, `target_guid?`, `business_operation_guid?`. Preview selalu menghasilkan `VALID|INVALID|DUPLICATE`; commit hanya mengeksekusi VALID, lalu per row menjadi `COMMITTED|FAILED`. File 100 row dengan 3 invalid menghasilkan preview `97 VALID + 3 INVALID`; commit maksimal 97 COMMITTED dan 3 tetap INVALID. Batch `PARTIAL` bila ada row gagal/invalid, `COMPLETED` hanya bila seluruh row valid dan committed; tidak menghapus hasil antar retry. Error domain per row dipetakan ke kode stabil `IMPORT_FIELD_INVALID`, `IMPORT_REFERENCE_NOT_FOUND`, `IMPORT_DUPLICATE_EXTERNAL_ID`, `IMPORT_SCOPE_MISMATCH`, `IMPORT_POLICY_NOT_ACTIVE`, `IMPORT_OPENING_RECONCILIATION_FAILED`; tidak memuat nilai bank/tax mentah atau PII di hasil download.

Commit memeriksa SHA-256 file, template version, policy/master watermark, entity scope, scan CLEAN, approval untuk opening dan sensitive data. Jika salah satu berubah, job 409 `IMPORT_SNAPSHOT_CHANGED` dan **tidak ada** row dieksekusi. Setelah commit dimulai, tiap row memiliki operation key permanen `(job_guid,row_no,template_version)` dan external identity registry unik; crash/retry dapat melanjutkan row tersisa tanpa mengulang row sukses. Domain service menerima command per row, bukan SQL langsung. Job mencatat total valid/invalid/committed/failed, cursor hasil, audit actor, dan report checksum; report status/hasil hanya terlihat dalam scope yang sama.
