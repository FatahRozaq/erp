# DATA-001 — Model data dan urutan migration MVP

**Status:** logical baseline lintas domain. DDL runnable tersedia untuk slice pertama dan sebagian baseline return Phase 2 di `backend/golang/services/{platform,commercial,operations,finance}/migrations/`. Tabel lain di bawah adalah kontrak kepemilikan dan constraint yang wajib diturunkan menjadi migration pada slice bersangkutan, bukan klaim bahwa migration sudah tersedia. Standar actor/versi/retensi mengikuti [database standard](../engineering/database-standards.md).

| Owner/schema | Agregat/tabel inti | Foreign key lokal; referensi lintas owner GUID | Unique/invariant penting |
|---|---|---|---|
| Platform `organization` | tenants, companies, legal_entities, branches, warehouses, assignment_history | company→tenant; entity→company; branch/warehouse→entity | satu parent efektif, tanpa interval overlap; immutable entity warehouse |
| Platform `master` | uoms, skus, customers, customer_accounts, vendors | SKU→UOM lokal; customer account→customer lokal; entity GUID lintas owner | code tenant aktif unik; account customer+entity unik |
| Platform `policy` | policy_versions, policy_activations, approval_instances/steps/decisions | instance→steps→decisions lokal | active range tidak overlap; decision step/version unik; maker≠approver |
| Commercial `sales` | sales_orders/lines, price_snapshots, credit_decisions, source_portions | line→SO lokal; customer/SKU/entity GUID | document_no permanen; source portion+action unik |
| Commercial `sales` return | sales_returns/lines | line→RMA lokal; delivery/source portion GUID | approved≤requested; received=accepted+rejected≤approved; operation GUID unik |
| Commercial `purchase` | purchase_orders/lines | line→PO lokal; vendor/SKU/entity GUID | document_no permanen; approved qty>0, received projection≤approved |
| Commercial `credit` | credit_accounts, exposure_buckets, deposits, override_records | bucket→account lokal; SO/invoice GUID | satu bucket aktif per source portion; account+entity unique; override consumed once |
| Operations `inventory` | receipt_limits, goods_receipts/lines, cost_pools, stock_balances, stock_movements, reservations | receipt line→header+limit lokal; PO/SKU/warehouse GUID | receipt ≤approved, cost pool per entity+SKU+ownership, movement source leg unik permanen |
| Operations `inventory` return | return_inspections/lines, return_inspection_limits | line→inspection+limit lokal; RMA/line GUID | cumulative received=accepted+rejected≤approved; operation GUID unik per batch |
| Operations `warehouse` | pick_tasks/lines, deliveries/lines, pod_evidence | line→delivery lokal; SO/reservation GUID | accepted+rejected≤shipped; evidence hash dan source portion unik |
| Finance `finance` | invoices/lines, payment_allocations, posting_intents, tax_documents | line→invoice, allocation→payment/invoice lokal | issued source portion unik; allocation≤open balance; external tax ref unik |
| Finance `finance` return | billing_source_portions, credit_memos/lines | memo line→memo+source portion lokal; delivery/RMA GUID | pre-invoice return+gross invoice≤delivered; credited≤gross invoice; memo per RMA unik |
| Finance `accounting` | fiscal_periods, accounts, journals/lines, gl_balances | line→journal/account/period lokal | debit=credit saat post; source+leg unik; closed period immutable |
| Tiap owner | audit_events, outbox, inbox, business_operation_registry | typed target GUID, tidak ada FK lintas owner | event ID, operation GUID dan consumer+event ID unik permanen |

Mutable aggregate/header/line/projection mengikuti `id bigint`, `guid uuidv7`, tenant/entity, `created_at/by`, `updated_at/by`, `deleted_at/by` bila soft delete sah, dan `version`. Posted movement/journal/audit append-only hanya punya metadata create serta actor sumber; reversal memakai record baru. Semua FK yang mungkin dibatasi composite tenant/entity agar relasi lokal tidak menembus scope. `numeric(20,6)` nilai/qty dan `numeric(24,10)` average/FX; uang JSON decimal string. Waktu instant `timestamptz`, business date `date` dan timezone entity terpisah.

**Migration order:** M0 identity/org/master/policy → M1 PO + receipt limit/GRN/cost pool/ledger → M2 sales/credit/reservation/delivery → M3 finance invoice/payment/GL. Setiap migration dibuat expand→backfill→switch→contract, review lock plan, dry run, rollback/forward fix, dan restore proof. Cross-owner GUID direkonsiliasi melalui event/owner lookup, tidak diberi SQL FK. Partisi ledger ditunda sampai volume menunjukkan kebutuhan karena PostgreSQL mensyaratkan partition key dalam unique/PK parent; registry unik permanen tetap diperlukan bila kelak dipartisi ([PostgreSQL partitioning](https://www.postgresql.org/docs/18/ddl-partitioning.html)).

Setiap service slice pertama juga mempunyai [migration runtime Operations](../../backend/golang/services/operations/migrations/runtime/000001_runtime.up.sql) dan padanannya di Platform/Commercial/Finance untuk operation registry, idempotency, outbox, inbox dan audit. Idempotency record aktif unik per tenant/principal/method/action/key, boleh dipurge setelah TTL melalui soft delete; business operation registry dan source key ledger tetap unik permanen.

Return Phase 2 memiliki migration awal pada [Sales](../../backend/golang/services/commercial/migrations/sales/000001_sales_return.up.sql), [Operations](../../backend/golang/services/operations/migrations/inventory/000002_return_inspection.up.sql), dan [Finance](../../backend/golang/services/finance/migrations/finance/000001_billing_return.up.sql). Migration ini membuat constraint sumber/kuantitas, tetapi belum membuat seluruh delivery, invoice, tax correction atau movement yang menjadi dependency saat Phase 2 diimplementasikan.

**Bukti siap persistence per slice:** DDL teruji PostgreSQL nyata, row example, constraint over-qty/duplicate/scope, index query dengan EXPLAIN pada dataset representatif, transaksi concurrency, dan reconcile ledger↔balance/AR↔GL. Sebelas migration yang sudah ada lulus apply lokal PostgreSQL 18 dan beberapa constraint utama; EXPLAIN representatif serta rekonsiliasi runtime menunggu data/handler. Slice berikutnya membuat migrasinya sebelum handler sesuai gate ini.
